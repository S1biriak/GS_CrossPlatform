# Демонстрация на защите

## Перед парой

Распаковать готовый релиз, запустить start-release.ps1, открыть http://localhost:5080/swagger. Импортировать коллекцию и окружение Postman, выбрать Library API — localhost. Убедиться, что порт не занят другой копией приложения. Проверить срок действия токенов; проще выполнить вход заново.

Для защиты использовать учебную библиотеку из релиза. Коллекция не изменяет начальные записи. Читатель R-004 должен оставаться с пятью активными выдачами для проверки лимита.

## Последовательность показа

1. **Запуск без IDE.** Показать окно сервера и Swagger. Объяснить, что self-contained архив содержит runtime и SQLite.
2. **Каталог.** GET /api/v1/books без токена. Затем search=МАСТЕР: найдутся два физических экземпляра одного названия.
3. **401.** GET /api/v1/reports/active-loans без Authorization. Показать статус и WWW-Authenticate: Bearer.
4. **Вход User.** POST /api/v1/auth/login. Показать accessToken, expiresAtUtc и роль, затем успешный запрос отчёта.
5. **403.** Попытка добавить книгу с User-токеном. Объяснить разницу с 401.
6. **Вход Admin.** Выполнить первый запрос коллекции; он также создаст уникальный runId. Выполнить вход User вторым запросом для остальных проверок.
7. **CRUD книги и читателя.** Запросы папок 02 и 03 создают записи, читают и изменяют их. ID подставляются автоматически. Показать запрет дубликата, архивирование и блокировку.
8. **Выдача.** Запрос 27 создаёт Loan с серверным временем и сроком по умолчанию 14 дней. Запрос 30 изменяет срок.
9. **Конфликты.** Повторная выдача, удаление активной выдачи, архивирование выданной книги и удаление связанного читателя возвращают 409.
10. **Четыре отчёта.** Папка 05. Назвать классы, участвующие в каждом отчёте. Обратить внимание на читателей без выдач в статистике.
11. **Возврат и удаление.** Папка 07 возвращает книгу, подтверждает её доступность, показывает 409 повторного возврата и удаляет тестовые записи в правильном порядке.
12. **Автоматический прогон.** Запустить всю коллекцию через Runner. Все запросы должны пройти; данные нового прогона также очищаются автоматически.
13. **Код.** Показать Book, Reader и Loan с методами; ReportService с Where, Select, Join и GroupBy; атрибуты Authorize; ограничение IX_Loans_OneActivePerBook и миграцию.
14. **Релиз.** Открыть страницу GitHub Release, показать архив приложения, Postman и инструкцию. Ссылку на релиз отправляет преподавателю студент.

## Ожидаемые начальные данные

- Всего 11 экземпляров книг, один архивный; обычный каталог возвращает 10.
- 5 читателей, один заблокирован, один без выдач, один у лимита 5.
- Всего 8 выдач: 7 активных, 1 возвращённая.
- Одна активная выдача просрочена относительно момента первого заполнения.
- LIB-001 имеет 2 выдачи и находится первым в рейтинге.
- Сумма TotalLoans в статистике всех читателей равна 8.

После ручного изменения начальных записей количества могут отличаться. Для новой чистой демонстрации распакуйте архив в новый каталог: это создаст отдельную БД и настройки без удаления предыдущей библиотеки.

## Типовые ответы при неполадках

- **Порт занят:** остановить предыдущий сервер или запустить start-release.ps1 -Port 5081 и изменить baseUrl.
- **401 после успешного входа:** проверить Bearer, выбранное окружение, срок токена и адрес сервера. После смены ключа/комплекта войти заново.
- **403 у User:** это ожидаемо для изменений; использовать Admin.
- **409 при удалении:** проверить активную выдачу и историю. Сначала возврат, затем удаление завершённой Loan, затем Book/Reader.
- **Нужен новый набор данных:** распаковать чистый релиз в новый каталог.
